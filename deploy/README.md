# Linux container deployment

Copy `deploy/.env.example` to `deploy/.env`. Replace every placeholder, deploy the V2 contracts, register the configured verifier, and supply a working Envio GraphQL URL. No private key is a browser build argument. The API fails closed without PostgreSQL, Redis, Envio, storage and scanner configuration in production. Missing AI credentials disable semantic verification with a recoverable error.

Run `docker compose --env-file deploy/.env -f deploy/compose.yaml config` before `build` and `up -d`. DNS for DOMAIN and objects.DOMAIN must point to this server. Only Caddy exposes ports. The objects bucket is private; signed downloads expire in 60 seconds. Migration is a one-shot dependency before the API and worker. ClamAV readiness is mandatory for uploads.

Envio 3 runs the committed `indexer/config.yaml` and `indexer/src/handlers.ts`. Configure the V2 addresses, generate the config and run `pnpm --filter @pactflow/indexer codegen`. Attach an Envio deployment using its supported infrastructure; supply its authenticated GraphQL endpoint to `ENVIO_GRAPHQL_URL`. The Compose stack includes a separate Envio PostgreSQL instance, Hasura and Envio 3.12.1. Generate runtime config from the verified address variables; Envio applies its own schema. Hasura is private and uses an admin secret. This configuration follows the [official self-hosting guide](https://docs.envio.dev/docs/HyperIndex/self-hosting) and [official example](https://github.com/enviodev/local-docker-example); the Linux runtime remains unverified on this host. Production does not use the development RPC fallback.

Backup PostgreSQL with `docker compose --env-file deploy/.env -f deploy/compose.yaml exec -T postgres pg_dump -U pactflow -Fc pactflow > backup.dump`. Encrypt and retain the dump off-host, alongside an object-store backup and the deployment-address records. Never put credentials in the backup log. Restore into a fresh isolated PostgreSQL volume using `pg_restore -U pactflow -d pactflow`; restore objects before workers resume. Verify private upload hashes, migration journal, index health, queue recovery and a receipt after restore. Redis persistence preserves pending queues, but database jobs are the source of truth.

Release requires an actual Linux build, PostgreSQL/Redis/storage/Envio integration run, TLS smoke, restore rehearsal and public Monad smoke. This development host has no Docker executable; these deployment checks remain BLOCKED until a runner/server is available.

### Google login and wallet access

Set `GOOGLE_CLIENT_ID` to a **Web application** OAuth client ID from Google Cloud. Add the exact public `WEB_ORIGIN` (`https://DOMAIN`, and `http://localhost:3011` for this local preview) to **Authorized JavaScript origins**. No client secret is used or exposed. The frontend reads enabled status from `/api/v1/auth/google/config`, loads Google Identity Services only when the login dialog is opened, and obtains the standard signed `name` claim. API validation uses Google's public keys, issuer, audience, expiry and a one-use five-minute nonce; Google account sessions have their own hashed tokens and logout endpoint.

Google registration/login is optional. Both guests and Google users must connect a wallet and sign the wallet ownership challenge before accessing protected collaboration actions. Google logout preserves wallet access; disconnecting the wallet revokes its wallet session and clears private cached data. Google identities are private account display information and do not replace a wallet's public work profile or grant fund permissions. If `GOOGLE_CLIENT_ID` is empty, the UI explicitly marks Google unavailable and the guest flow remains usable.

Setup reference: [Google Identity Services configuration](https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid) and [server-side token verification](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token).
