# Five-step creation

Client wallet session → outcome/context/skills → named deliverables with criteria and required evidence → configured verification → parties/budget/deadlines/revisions → immutable review. Multiple milestones hash independent policies. Default two revisions; supported range 0–10. Acceptance dates and review hours must be valid before a transaction.

PactWizard creates, saves the hash-matching spec and policies, checks balance/allowance, obtains token permission and funds with real SDK receipts. Provider capability flags disable unavailable semantic verification. AI suggestions remain editable and require explicit use. Local tests exercise wallet refusal and retry without changing nonce.

## Acceptance and boundaries

V2 factory/registry configuration and settlement token are mandatory. Public wallet and provider smoke is blocked; local signing tests are not public Monad evidence.

Required acceptance: actual user flow, English/Chinese, keyboard and mobile, empty/loading/failure states. Executed gates and evidence are recorded in `qa/PRODUCTION_AUDIT.md`; full source requirements are in `product/MASTER_DIRECTIVE.md`.
