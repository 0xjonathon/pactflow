# Verification

Normalize evidence → deterministic rules → external checks → optional semantic judgment → policy aggregation → canonical report → registered verifier proof. SINGLE, THRESHOLD and ALL_REQUIRED aggregation enforce cardinality, mandatory rules, score and confidence.

Creation exposes manual review, deterministic JSON/website/GitHub CI, hybrid and configured semantic JSON. GitHub evidence pins a full commit and actual check names/app/repository identity. No untrusted repository build executes on the API host. Oracle/custom adapters require registry identity/version, HTTPS authorization and signed fresh context. Missing configuration produces recoverable ERROR, never a passing proof.

## Acceptance and boundaries

Reports bind current sequence, evidence, policy, version/model, verdict and report digest. Worker claims are atomic; durable signed raw transaction is saved before broadcast and retried as the same transaction. Redis runtime, real providers and live GitHub fixture checks remain externally unverified.

Required acceptance: actual user flow, English/Chinese, keyboard and mobile, empty/loading/failure states. Executed gates and evidence are recorded in `qa/PRODUCTION_AUDIT.md`; full source requirements are in `product/MASTER_DIRECTIVE.md`.
